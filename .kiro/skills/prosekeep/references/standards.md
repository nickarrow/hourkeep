# Standards and precedence

Use the named, sourced references in `standards/`. All are short independent syntheses, intended to be applied together with the author or project's own editorial decisions.

| ID | Reference | Guidance |
| --- | --- | --- |
| `18f-content` | 18F Content Guide | Voice, plain words, headings, task content and technical instructions |
| `federal-plain-language` | Digital.gov / PlainLanguage.gov | Audience, organization, active verbs, complexity and reader testing |
| `gsa-content` | GSA Web Style Guide | Timeliness, usefulness, duplication, accuracy and lifecycle |
| `accessible-content` | USWDS, 18F Accessibility and W3C | Semantic headings, links, alt text, tables and labels |
| `source-evidence` | Prosekeep and Vloora method | Evidence states, source preservation and claim audit |
| `ai-writing` | Prosekeep with humanizer references | Structural AI-writing patterns and authorial fidelity |
| `publishing` | Prosekeep and GSA | Source-first publication, review roles and QA |

## Precedence

1. Current explicit owner or author directions govern the work, within applicable laws and safety requirements.
2. Project `EDITORIAL.md`, positioning and product-source documents specify local voice, page roles, evidence and publishing rules.
3. Explicitly selected style profiles (`.editorial.json`) govern mechanical checks and house conventions.
4. External standards provide useful guidance where the above are silent. Mandatory legal or accessibility obligations still apply when relevant; Prosekeep cannot determine compliance.
5. A matching regex or model-generated suggestion is never authority to change the author's judgment or invent facts.

External guides sometimes disagree. For example, Vloora spells out 'percent' in paragraphs whereas GSA style normally uses `%` with figures. Respect the governing project's chosen convention rather than silently joining contradictory requirements.
