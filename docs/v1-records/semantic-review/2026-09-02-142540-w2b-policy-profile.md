# Policy profile module and repo-wide policy-literal removal (W2b)

`ad8ac87..HEAD` — 9 commits, 40 files, +4539/−284

Introduces `src/lib/policy/` as the single home for every policy value, and rewires 19 files to read
thresholds from it instead of writing them down. The module is four files: a 36-field `PolicyProfile`
interface with a runtime field manifest and an ownership record, a `FEDERAL_DEFAULT` statutory-floor
profile, two derived values (`incomeThreshold`, `confidenceHedge`), and two transition rules answering
"does this requirement reach me yet" (42 CFR 435.915 and 435.559(c)). W5's standalone
`FEDERAL_DEFAULT_REVIEW_PERIOD` is folded in, its `renewalPeriodMonths` merged with the schema's
`renewalIntervalMonths` — one quantity that had two names. Three new guard tests police the result: an
in-CI literal scan across 19 files, a spelt-number scan across all of `src/`, and two components added
to the no-verdict render guard.

**Watch for:** the in-CI literal scan's regex excludes `$` as a preceding character, so **21
dollar-prefixed policy literals survive in three files the test certifies as clean** (confirmed);
`GettingStartedContextual.tsx` now computes a difference from the profile while printing the threshold
as a literal, so the two disagree the moment the wage moves (confirmed); `transition.ts` and
`confidenceHedge` have **zero production consumers** (confirmed); `POLICY_FIELD_OWNERS` names three
unique consumer paths, none of them the fifteen files this wave actually wired (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The injection seam is not uniform, and the split is load-bearing for the next wave. The six `src/lib/`
modules take an optional `policy` parameter defaulting to `FEDERAL_DEFAULT`, verified by tests that pass
a mutated profile and assert the answer moves. The twelve content and UI files instead bind module-scope
constants (`const HOURS = FEDERAL_DEFAULT.requiredHours`) at import time, which cannot follow a per-state
profile at all. No production call site passes a profile anywhere, so today the two are
indistinguishable; W3 pays the difference across 19 constants in 9 files plus 3 more reading inline.

The literal-removal work was shaped by its own instrument. The scan pattern was inherited from W2a with
`$` inside the excluded preceding-character class — legitimate against identifier matches, fatal in copy
files where the income threshold is written `$580`. Every literal the regex can see was fixed; every
literal it cannot see was left. The wave's "60 literals across 14 files" count, its site table, and its
acceptance criterion "the grep returns 0" are all readings from that instrument.

`POLICY_FIELD_OWNERS` is a real check on one of its two arms and an unverifiable note on the other. The
`consumer` arm asserts the named path exists *and* imports `@/lib/policy` — but only 13 of 36 fields name
a consumer, resolving to three unique paths, all inside or beside the policy module. The `wave` arm
asserts a label pattern and 20+ characters of prose, six of the eight labels used have no wave file, and
nothing fails when a wave closes without reading its field.

`incomeThreshold(profile)` as a function rather than a stored field achieves what it claims, and
`ReviewPeriodPolicy = Pick<PolicyProfile, …>` is the right relationship over an interface plus adapter.
The schema then reintroduces the bug the `Pick` removed: `verificationMonthsRequired` and
`moreFrequentVerification.monthsRequired` are the same quantity declared twice, nothing reconciles them,
and the review-period module reads only the first.

Both transition functions are finished, heavily tested, and unreachable. The domain notes call
§ 435.559(c) "the single most reassuring fact in the rule for currently-enrolled users, and nothing in
the app told them before now." After this wave, still nothing does.

## The seam: injected in lib, module-bound in UI

```
src/lib/policy/  ──┬─→ calculations.ts            policy?: PolicyProfile = FEDERAL_DEFAULT
                   ├─→ recommendationEngine.ts     policy?: PolicyProfile = FEDERAL_DEFAULT
                   ├─→ exemptions/calculator.ts    policy?: PolicyProfile = FEDERAL_DEFAULT
                   ├─→ storage/income.ts           policy?: PolicyProfile = FEDERAL_DEFAULT
                   ├─→ reviewPeriod.ts (×5)        policy?: ReviewPeriodPolicy = FEDERAL_DEFAULT
                   │
                   └─→ content/helpText.ts         const HOURS = FEDERAL_DEFAULT.requiredHours
                       exemptions/definitions.ts   const HOURS = …
                       help/HourTrackingHelp.tsx   const HOURS, INCOME_MINIMUM = …
                       assessment/NoticeQuestion   const HOURS, INCOME_MINIMUM = …
                       onboarding/GettingStarted…  const HOURS, INCOME_MINIMUM = …
                       income/IncomeStatusInd…     const INCOME_THRESHOLD = …
                       income/SeasonalWorkerView   const INCOME_THRESHOLD = …
                       results/page.tsx            const HOURS, INCOME_MINIMUM, SEASONAL_MONTHS
                       utils/payPeriodConversion    const FEDERAL_MINIMUM_WAGE, REQUIRED_HOURS, …
                       (+ settings, tracking, export read FEDERAL_DEFAULT inline)
```

The upper group is per-call. `policyInjection.test.ts` passes `{ federalMinimumWage: 9, requiredHours: 40 }`
and asserts `hoursNeeded`, `primaryMethod`, and the interpolated copy all move; the assertion
`expect(result.reasoning).not.toContain("$580")` is the one a surviving literal fails. The lower group is
fixed at import time. `recommendationEngine.ts` threads its profile into `calculateExemption`, but no
component calls either with a profile, so the per-state work is entirely ahead.

`helpText.ts`'s header argues the module-load binding costs nothing because both values are statutory
rather than state elections — 42 CFR 435.552(a) fixes 80 hours, and (a)(6) ties income to the FLSA wage
which states may not substitute. Correct for those two. The same file then binds `SEASONAL_MONTHS` from
`seasonalMethod`, which *is* an election under 42 CFR 435.603(h)(3), and the header says the resulting
hedge is "true but incomplete." The pattern was copied verbatim into `results/page.tsx` and
`recommendationEngine.ts`. W7a inherits three copies of it.

The secondary reason given — that turning content exports into functions would make
`no-verdict.content.test.ts`'s recursive walk depend on which profile it chose — is real but cheap to
solve: the walker calls the factory with `FEDERAL_DEFAULT`, or with two profiles.

## The literal scan cannot see a dollar sign

`policyInjection.test.ts` scans 19 files with:

```
/(^|[^0-9._$A-Za-z])(80|580|7\.25|4\.33|2\.17)([^0-9%A-Za-z]|$)/
```

`$` is in the excluded preceding-character class, so `$580` never matches. Verified:

```
MISSES  benefit: "Counts when income is under $580"
MISSES  "Compare that average against the $580 threshold"
FIRES   const t = 580;
FIRES   "the 80-hour requirement"
```

Excluding `$` guards against matching inside identifiers, since `$` is a valid JS identifier character.
In copy files that is the wrong trade: the dominant written form of the income threshold *is* `$580`.

Scanning the same 19 files with the test's own comment stripper and `policy-literal-ok` filter for
`\$(580|7\.25)`:

| File | Live hits |
|---|---|
| `src/content/helpText.ts` | 14 |
| `src/components/onboarding/GettingStartedContextual.tsx` | 5 |
| `src/components/income/SeasonalWorkerView.tsx` | 2 |

All three are in the test's `COPY_AND_UI` array, under a test named "%s states no threshold as a
literal". The surviving `helpText.ts` strings include the whole seasonal block — `"$3,480 ÷ 6 months =
$580 per month average"`, `"Average: $580. Threshold: $580."` — and four of the five `complianceOptions`
descriptions.

The shape of what got fixed makes the boundary visible. In `GettingStartedContextual.tsx` the diff
converts `const needed = 580 - income` to `INCOME_MINIMUM - income` and every `Threshold: 80 hours` to
`Threshold: ${HOURS} hours`, and leaves every `Threshold: $580` untouched — the regex's visibility limit
drawn through a single function. The 60-mutation harness missed it too: every re-hardcoding mutation
writes a bare literal (`const HOURS = 80;`, `= 580;`), never `$580` into a string.

## GettingStartedContextual now contradicts itself

```ts
const needed = INCOME_MINIMUM - income;          // from the profile
...
return `Recorded: $${income} a month. Threshold: $580. Difference: $${needed}. …`;
```

At $7.25 the two agree. At $9.00 the user is told the threshold is $580 and the difference is
$720 − income. A stale literal is wrong once; this is wrong and self-refuting on the same line.

`results/page.tsx` — which the wave file labels "near-duplicate of the results page" — has the identical
function fully interpolated. One of two near-duplicates was finished.

## POLICY_FIELD_OWNERS: a real check over three files

One assertion is load-bearing. Requiring a named `consumer` to both exist *and* contain
`from "@/lib/policy"` is what stops the record from meaning "the file where this number belongs":

```ts
expect(source, `${field}: ${owner.consumer} is recorded as a consumer but does not
  import from @/lib/policy`).toMatch(/from "@\/lib\/policy"/);
```

What it guards is much narrower than the wave. Computed from `types.ts`:

- 13 fields name a consumer; 23 name a wave.
- The 13 resolve to **three** unique paths: `src/lib/policy/derive.ts`,
  `src/lib/policy/transition.ts`, `src/lib/reviewPeriod.ts`.

Not one entry names `calculations.ts`, `recommendationEngine.ts`, `exemptions/calculator.ts`,
`storage/income.ts`, `content/helpText.ts`, or any of the twelve UI files this wave wired.
`requiredHours` — read in 13 places — records `src/lib/policy/derive.ts`, with the prose "and the monthly
hours threshold read by calculations.ts". The prose knows; the checked field does not. Deleting
`@/lib/policy` from `helpText.ts` or `calculations.ts` would leave the ownership tests green.

Two of the 13 "live consumers" are `label` and `confidence`, whose consumer is `derive.ts` —
specifically `confidenceHedge`, which nothing calls. So `consumer` can mean "reaches a screen", "is read
by another library function", or "is read by a library function nobody calls", and it does not
distinguish them.

The `wave` arm asserts a label pattern and `why.length > 20`. `W6a`, `W7a`, `W7b`, `W8a`, `W9a`, `W9b`
have no file in `docs/hr1-readiness/waves/`. Nothing fails if W4 closes without touching
`frailtyListStructure`. `SPELT_ALLOWLIST`, three files away, shows the missing half: "every allowlisted
file still contains the phrase it is excused for" turns red the moment W3 fixes one.

So: mechanism over three files, documented speculation over the rest. Still better than W5's undocumented
version, and worth stating that way rather than reading 36 owner entries as 36 checks.

## Two names for the verification month count

```ts
/** 42 CFR 435.556(a)(2)(ii). Months required between more-frequent verifications. */
verificationMonthsRequired: number;
/** 42 CFR 435.557(d). `false` means the state verifies only at renewal. */
moreFrequentVerification: false | { intervalMonths: number; monthsRequired: number };
```

Same quantity, two declarations. `verificationReviewPeriod` reads `policy.verificationMonthsRequired` and
never looks at the union. A state electing `{ intervalMonths: 3, monthsRequired: 2 }` with
`verificationMonthsRequired: 1` left at the floor produces a one-month verification period, silently. No
test asserts agreement.

Latent today, because `FEDERAL_DEFAULT` sets `false`. It is also the failure this wave eliminated on the
renewal side, where `renewalPeriodMonths` and `renewalIntervalMonths` were merged for being "the same
quantity under two names". `verificationMonthsRequired` is owned by `reviewPeriod.ts` today and
`moreFrequentVerification` is assigned to W9a, so the reconciliation lands on a wave inheriting a live
reader it must not break.

Smaller related inconsistency: "not applicable" is `false` for `moreFrequentVerification` and `null` for
`unableToVerifyAtVerification` — one fact, two encodings, adjacent fields.

## transition.ts is a library nobody calls

`applicationRuleset`, `renewalInitiationWindow`, `confidenceHedge`: zero references outside
`src/lib/policy/` and its tests, and zero in `e2e/`. Same for `interpretiveRisk`,
`POLICY_PROFILE_FIELDS` and `POLICY_FIELD_OWNERS`.

The three-valued return is the right shape, not defensive over-engineering. Both questions have a genuine
third answer for a stated reason: § 435.915 turns on a filing *date* while the app stores a *month*, and
§ 435.559(c) turns on when a renewal was *initiated*, which CMS reports only as "60 to 90 days" across
"many States". A boolean would have to invent one of those, and the invention runs in the direction that
stops someone gathering evidence. Splitting `triggerCitation` (rule text, 91 FR 33478) from
`leadDaysCitation` (preamble, 91 FR 33416) is right for the same reason — the tiers differ inside one
answer, and merging them produces one confident-looking string.

`why` prose belongs here, and the tests are why that is safe. The per-sentence hedge check is the
strongest assertion in the diff:

```ts
for (const sentence of why.split(/(?<=[.?!])\s+/)) {
  if (!absolutes.test(sentence)) continue;
  expect(sentence, `${month}: unhedged prediction`).toMatch(hedges);
}
```

It bans an unhedged negative prediction rather than banning the words, and the comment records that the
blanket version fired on correct copy. Copy this far from a render tree is only checkable because the
assertions are properties.

The cost is that the reassuring answer reaches nobody. Under `FEDERAL_DEFAULT` every renewal due through
March 2027 returns `"before"` — one month further than the steering doc's "January or February", computed
and pinned by a test. Nothing renders it. Both functions also need inputs the app does not store: no
filing date, and no renewal due month outside the W5 anchor. The `straddles` arm is unreachable under any
real profile (a 30-day-wide window never lands either side of a first-of-month implementation date) and
is tested with a synthetic `{ min: 60, max: 120 }` — flagged as such, but it is a third arm existing for
a state whose lead time nobody has published.

## incomeThreshold as a function, and ReviewPeriodPolicy as a Pick

`incomeThreshold(profile)` does what the field could not. The prior encoding was `readonly
incomeThreshold: number` with "Derived: never hardcode 580" in a comment — `readonly` prevents
reassignment, not contradiction, so a per-state profile could have stored a number that was not
wage × hours. With no field and one function that is unrepresentable, and `expect("incomeThreshold" in
FEDERAL_DEFAULT).toBe(false)` pins it. The test that earns its place is the mutated one:

```ts
const raised = { ...FEDERAL_DEFAULT, federalMinimumWage: 9 };
expect(incomeThreshold(raised)).toBe(720);
```

Asserting 580 cannot distinguish a derivation from a constant; asserting 720 can. The rounding test
records that its first version used 7.255, whose product with 80 is cent-exact in binary, so deleting
`Math.round` left it green — mutation testing finding a vacuous test, written down.

`Pick<PolicyProfile, …>` over a parallel interface plus an adapter bought three things at once: one
declaration per field type, no mapping to drift, and the discovery that `renewalPeriodMonths` and
`renewalIntervalMonths` were one quantity. The `source` shape change from `string` to
`{ citation, url?, retrievedAt }` came free, and `reviewPeriod.test.ts` kept asserting `/435\.556/`
against `source.citation` rather than relaxing to the section family, which a range would have satisfied.

One caveat. The `Pick`'s stated purpose is that "the module's dependency surface stays visible: these
seven fields are what review-period arithmetic depends on." Every call site passes
`{ ...FEDERAL_DEFAULT, … }` — all 36 fields, accepted structurally. The narrowing is visible at the
declaration and invisible where it is used.

## The deprecated re-exports outlived their stated reason

`payPeriodConversion.ts` keeps three aliases with a recorded justification:

> They are re-exported rather than deleted because `INCOME_THRESHOLD` had three live importers at the
> start of W2b … `storage/income.ts` now takes a profile instead, leaving **two**, both components.

Both components — `IncomeStatusIndicator.tsx` and `SeasonalWorkerView.tsx` — were changed in this same
diff to declare their own `const INCOME_THRESHOLD = incomeThreshold(FEDERAL_DEFAULT)` and import only
`formatCurrency`. Production importers of all three aliases: **zero**. The sole importer is W0's
characterization test.

Keeping them is still defensible — that test asserts `INCOME_THRESHOLD === FEDERAL_MINIMUM_WAGE ×
REQUIRED_HOURS`, a relationship worth preserving through W7a. But the recorded reason describes consumers
this wave removed: the "re-read the target before claiming a change is done" rule, applied to a comment
rather than a file. Same class as `reviewPeriod.ts:47`'s "thirty-five" and `policy.test.ts:507`'s "all
35" against a 36-field manifest.

## Guards and mutation coverage

The new guards are built better than the ones they follow. `mustNotFire` fixtures exist from the first
commit rather than after the first false positive, and the six prose sentences the first spelt-number
pattern wrongly matched are pinned so a later tightening breaks loudly. Excluding `one` from that pattern
was decided by running the scan, and argued rather than asserted: the federal default for both
month-count elections *is* 1, so a spelled "one month" states the value the profile holds.
`SPELT_ALLOWLIST` has the expiry test `POLICY_FIELD_OWNERS` lacks, with `owner` as a closed union so
widening it requires a type change. The comment stripper carries a positive twin,
`expect(found).toEqual([6, 7, 8])`, without which every scan could pass vacuously.

Two gaps. The stripper is duplicated, 30 near-identical lines across `no-spelt-policy-value.test.ts` and
`policyInjection.test.ts`, in a repo that has `src/__tests__/support/` for exactly this. And the mutation
harness, 60 mutations deep, contains no mutation reintroducing a threshold as `$580` in a string — the
one mutation that would have surfaced the scan's blind spot. `scripts/mutate-w2b.sh` is committed while
its own header reads "Temporary; deleted at wave close."
