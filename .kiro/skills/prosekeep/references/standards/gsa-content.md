# GSA content standards and lifecycle

Sources: [GSA Content Standards](https://www.gsa.gov/reference/gsa-web-style-guide/content-standards), [GSA Web Style Guide](https://www.gsa.gov/reference/gsa-web-style-guide), and [GSA Written Style](https://www.gsa.gov/reference/gsa-web-style-guide/written-style). The GSA standards govern designated GSA properties; Prosekeep exposes them as reference guidance for other organizations, not as universally binding policy.

## Six content-quality dimensions

- **Timely:** Record when content was published or last reviewed. Confirm that dates, access routes, ownership, events, fees and service statuses are still current. Define an appropriate review cadence in the site's own policy.
- **Useful:** Serve the person's purpose with actionable information, clear names and meaningful links.
- **Readable:** Use plain language suitable for the audience. Readability formulas may be useful diagnostics but do not certify comprehension.
- **Nonduplicative:** Each page has a distinct job. Consolidate redundant explanations and point to their canonical home.
- **Accurate:** Verify consequential claims and obtain subject-matter review when required. The reviewer must distinguish reported outcomes from verified ones.
- **Consistent:** Apply the project's adopted written and visual conventions across interfaces, releases and documents.

## Mechanics that remain configurable

GSA written style contains its own rules for capitalization, dates, links, numbers, percentages, abbreviations, contact information, and button labels. Some differ from other organizations' choices. For example, GSA generally uses a percent sign with figures, while Vloora spells "percent" in running text. Use the project's chosen rule and record why; never combine conflicting styles without precedence.

## Publishing checks

Document page owner, last review, primary reader, content role, required sources, and whether an alternate or old page needs a redirect. Check that no dead-end or placeholder page is being launched. Check source changes against the generated site and the actual navigation and metadata; use build checks rather than editing compiled HTML.

These are editorial and review criteria. Prosekeep does not automatically enforce all GSA lifecycle obligations or claim government compliance.
